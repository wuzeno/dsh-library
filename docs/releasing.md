## 当前状态

`1.0.0` 为正式版：每个工作区自动建立独立原文件库，统一存放在用户选定的本机根目录，由「资料库」菜单集中管理，支持任意格式原件，对话中可选择是否参考资料库。导入仍只保存原件和元数据，按需作为原生聊天附件使用，不预提取、不全文索引、不 OCR。本清单中打勾前不得宣称对应项已验收；本次描述与版本号统一未改变运行行为，测试结果为本地 246 项（244 通过、2 跳过）。

## 源码与打包前

- [ ] 核对 README、版本、许可、目标 DSH `0.2.1-rc.3` 和限制。建立仓库后才填写 repository/homepage/bugs，不猜账号。
- [ ] 核对运行入口 store 不 import、不调用 `documents.js` 或 parse 模块，不预提取、不全文索引、不 OCR、不后台理解媒体；历史模块及其测试可暂留，不作为当前运行能力宣传。
- [ ] 提交源码、文档、锁文件和 CI；不提交 node_modules、release、资料根目录、历史 extracted 缓存、个人 profile、会话附件、日志或秘密。
- [ ] 在后续有授权的验证阶段执行 `pnpm install --frozen-lockfile --ignore-scripts` 与 `pnpm run test:all`，记录 Windows/Linux、Node 22/24 的实际结果；不得把旧测试结果算作新版按需附件验收。
- [ ] 检查保留依赖的许可证、安全公告与安装脚本策略。依赖存在不意味着原件库运行入口会调用解析器。
- [ ] 检查 UI 已移除提取文本、分段、全文检索测试与重试解析；保留下载原文件、排除/纳入 AI 参考、回收恢复。

## 目标宿主实测（均待验收）

- [ ] 获得单独同意后通过目标 DSH 插件管理器更新安装，不手改 profile/package.json 或 cordis patch。记录宿主版本和包版本。
- [ ] 检查侧栏、深浅主题、首次配置、旧/新工作区、立即提问、改名/删除、重启持久性、停用及卸载保留资料。
- [ ] 从旧 `cloudConsent: true` 与 false 分别升级，确认 `settings.originalConsent` 默认 false，不静默授权；仅用户重新在“存储与隐私”确认后可使用原件。根目录保存不能代替原件使用同意。
- [ ] 检查未同意、撤销同意、通用模式、跨库未授权、fork/新会话、会话归属变化、排除、回收、停用库时，文件列表和打开均不能越权。异步交付前再次检查，撤销不能被旧检查绕过。
- [ ] 检查通用模式不注入资料元数据正文，拒绝 `library_files` / `library_open`。资料库模式列获授权文件名/来源，不预读全文；未命中正常用模型知识回答，区分引用、补充和推断，不编造资料引用。
- [ ] 用 TXT、DOCX、PDF、表格及非文本样本验证 `library_open` 经 `ctx.attachments.saveFile` 交付原生 file block，宿主按同聊天附件机制投影只读路径，后续文件工具/skills 确能按需读取。不能以返回字符串路径或成功下载代替此项。
- [ ] PNG/JPEG/WebP/GIF 验证仅 open 时按魔数识别，并通过 `ctx.attachments.saveImage` 返回 image block；伪扩展名、图片准入失败等场景明确退 generic 文件，不覆盖原件，不伪称视觉模型已看图。其他媒体不后台转录或理解。
- [ ] 检查模型请求/会话附件实际数据流，提示原件可能整份发送并进入历史。关闭同意阻止新交付，但不能撤回已发送附件或模型已看过内容；不要写成完全离线或可撤回承诺。
- [ ] 验证任意格式导入与浏览器鉴权原件下载；默认 50 MiB、整数 1–200 MiB 设置、空文件拒绝、库容量 2000（含回收）、指纹重复拒绝。附件准入限制不等同于上传限制。
- [ ] 保留批量扫描预算：2000 文件、5 GiB、10000 条目、32 层、忽略目录、预览确认、停止后续上传与错误报告；超总预算不开始部分上传。
- [ ] 用旧 ready/error/stored 记录验证均可按需使用，不改原件、不重解析、不删除旧 extracted 目录；备份包含历史数据。

## 生成安装包

```sh
pnpm pack --pack-destination release
```

包内仅含清单允许的运行源码、patch、locale、图标和文档；实际解包核对 `.tgz`，不能只看 files 配置。源码仓库可保留历史解析测试与辅助模块，文档必须明确其不在 store 运行路径。运行无构建步骤，scripts 不依赖安装时 prepare/postinstall。

## GitHub 操作

用户先选择仓库、账号、公开/私有并明确授权推送，不擅自建立公开仓库或上传资料。MIT 默认允许再分发，其他许可偏好应在首次公开前决定。

后续发布 `v0.2.0` 时附包、校验和、目标版本、实际验证结果与未完成项。自动化检查和真实宿主按需附件验收分开说明；未完成安装/联调不得宣称验收通过、完整多模态理解、零幻觉或完全离线。未配置自动 GitHub Release/npm 发布；后续凭据仅在平台 secret 中设置，不交给模型或写入仓库。
