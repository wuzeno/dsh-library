# 架构、安全边界与恢复

## 1.0.0 定位与接入

每项目原文件库：导入仅保存任意格式原件与元数据，工作时按需作为聊天附件使用。不预提取、不全文索引、不 OCR，不后台理解媒体。目标接口版本 DSH `0.2.1-rc.3`；真实宿主尚未更新安装及完成按需读取联调，下列为预览接口设计与待验证边界，不是实机验收结论。

仅使用公开插件机制：

- Host `storageDomain.open` 保存私有元数据；`workspaceRegistry.list` 提供权威工作区 ID 和会话归属。
- Host `domain/changed` 观察 workspace 域变化，合并通知后重新读取 registry，并在会话工作前核对新工作区；不从 cwd 或 UI 选择猜归属。
- Host `connection.fetch.register` 使用已认证共享管理路由，原件下载是同一路由的独立 `download` 动作，不启动额外服务器。浏览器管理下载与模型附件交付是不同通道。
- Host `tools.register` 提供状态、`library_files`、`library_open` 及受限管理能力；模型不能更改根目录、授予跨库权限或确认回收。
- Host `agent/pre-step` / `systemPrompt.section/context` 仅用于本轮模式、权限与原件按需使用规则，不运行全文检索，不提前读取并注入原件正文。不直接改写 assembled messages 或 session events。
- Client `sidebar.panellist`、`main`、`conversation.input.left` 提供菜单、管理页及会话范围控件，使用宿主 React 与主题 token，不替换 root 或注入独立应用。

## 原件按需路径

1. 浏览器选文件或扫描文件夹，确认后上传字节；store 校验大小、路径、指纹与库容量，复制到 UUID 派生原件路径，并保存元数据。导入不调用解析器，不向模型发送文件。
2. 资料库模式下，`library_files` 仅列当前获授权文件的名称、来源与必要元数据，不搜索或理解文件正文。列举结果不代表已经读取所有文件。每次元数据最多约 8000 字符、每轮累计 24000 字符；截断保留正确分页位置。每轮列举/打开合计最多 10 次，交付原件累计不超过 200 MiB，不将文件正文计入文字索引。
3. `library_open` 在核对模式、`settings.originalConsent`、会话归属、跨库范围、停用/排除/回收状态及安全原件路径后，按需读取单个原件。
4. 普通文件通过 `ctx.attachments.saveFile` 返回原生 `file` block。宿主使用同聊天附件的投影，把文件映射到只读路径；文件工具或 skills 再按需读取，不由插件伪造路径或把文件转成全文工具结果。PTC/run_code 的通用文件子结果不会自动附加 file block，因此返回值同时含 `readPath`：按宿主相同接口 `attachments.fileHostPath(ref)` → `fs.processPathFromHostPath(hostPath)` 获取当前执行环境的真实句柄。PTC 中须打印/返回该字段再读取。provider/映射缺失或出错时返回 null 并说明不可读，绝不回退原库路径。
5. 仅 open 时用魔数识别 PNG/JPEG/WebP/GIF；符合条件时通过 `ctx.attachments.saveImage` 返回原生 `image` block，不修改或覆盖原件。图片准入失败退回 generic 文件并明确说明，不能伪称图片已交给视觉模型。

宿主原生 block、附件准入、只读投影、工具/skills 后续读取均需真实宿主联调。文件能保存、列举或下载，不证明模型能理解该格式；音视频不后台转录、解码或摘要。不要为附件契约缺失静默恢复旧全文提取路线。

资料库模式保留值 `library`：参考授权资料，区分有原件依据的引用、模型知识补充及推断。未找到相关资料、文件暂不可读或库不可用时可正常使用模型知识回答，说明限制而不编造引用。通用模式保留值 `general`：仅提供不含库/文件信息的模式标记，要求不把历史资料库附件作为本轮依据；不注入资料元数据或正文，`library_files` 与 `library_open` 均拒绝。切换模式后停止新的资料交付，但不能物理移除历史附件；需严格隔离旧资料影响时另开会话。两种模式均不能借知识补充绕过隐私或跨库授权。

## 同意迁移、身份与授权

`settings.originalConsent` 默认 `false`。旧 `cloudConsent` 仅对应检索片段，**不得静默升级为整份原文件使用权限**。无论旧值为 true/false，升级后均需用户重新在“存储与隐私”确认原件使用。根目录确认、原件使用同意及会话跨库授权是不同决策，设置位置不能代替发送同意。

原件同意与当前有效会话授权共同约束文件列表及打开，不以模型参数授予权限；关闭同意后阻止新的插件交付。原件可能经当前模型链路发送到云端或进入会话附件/历史，关闭不能撤回已发送附件或模型已看过内容，也不能撤销其他广泛文件权限工具的能力。新会话可减少旧上下文影响，但不撤回已发送数据。

工作区以 `Workspace.id` 为身份，根据 registry 的 `sessionIds` 找会话归属。默认库来自工作区关联。额外跨库仅由已登录浏览器范围控件明确授权到精确 sessionId，并绑定 workspaceId；保存授权时对默认库与显式授权库去重后的并集校验，最多 8 个库；fork、新会话不继承，会话归属变化即失效。保存范围时记录当时默认库，避免解除关联后旧默认库变成隐式额外授权。管理页是全局面板，不能替会话决定范围。

列表、打开与管理方法均在 Host 校验当前范围，工具不能传 libraryIds 或路径扩大权限。异步操作须在交付前重新核对模式、同意与范围；撤销后不能继续用先前检查结果交付原件。历史附件和其他工具不属于可撤回范围。

## 管理 HTTP 与文件夹扫描

路由使用 DSH 已认证 shared Fetch channel，再经 connection.admit 仅允许 browserPeer，拒绝独立 API/tool peer。管理 POST JSON，上传 POST application/octet-stream；需要自定义头，无 CORS 放行。JSON 实际流硬限 15 MiB，非 import 请求另限 256 KiB；兼容小文件 JSON import 不意味着放宽预算。二进制流按当前单文件设置逐块限制，读取时设置降低也拒绝，绝对上限 200 MiB。文件名/来源相对路径头受限、解码后再校验，不将内部堆栈返回给模型。

浏览器枚举支持 legacy WebKit reader 持续读到空批次、modern FileSystemHandle 与 webkitdirectory。扫描仅获取元数据，预览确认后逐文件读取、串行上传；单批最多 2000 文件、5 GiB，最多检查 10000 条目，深度超过 32 的子目录跳过报告，跳过常见依赖/版本控制目录。超总预算整批不上传，取消预览不导入；停止后续导入等待当前请求结束，已导入不回滚。空文件仍拒绝，错误原因最多展示 200 条。

`file.sourcePath` 仅作显示、筛选与溯源，拒绝绝对路径、控制字符、空段、`.`/`..` 和末段文件名不一致；不用于构造原件磁盘路径。不能因任意格式不支持解析而拒绝保存。

这些机制防止普通跨站请求和独立 API peer 自行授权，不防御恶意浏览器扩展、受控浏览器会话或本机任意代码执行。Host 插件是受信任代码，不是 OS 沙箱。

## 原件与历史代码边界

默认单文件 50 MiB，可设整数 1–200 MiB；每库最多 2000 文件，包含回收区。原件路径仅由受信任本机 root 与 UUID 派生。配置 root 时拒绝等于或位于任何已登记库目录内（包括停用、待删除库）；建库再次校验 root 与候选目录，拒绝库目录相互包含。路径比较同时使用规范化绝对路径与 realpath（不存在尾段解析至最近现存祖先），防止旧记录的别名绕过；常规 root 作为多个并列库的共同父目录仍允许。删除前及递归删除前拒绝其他登记库等于或位于目标目录内，保护旧版已形成的嵌套记录，不自动迁移或删除它们。每次 I/O 前检查祖先 lstat/realpath 与所有权标记，拒绝符号链接/目录联接；这不是抗恶意本机并发改路径的原子 openat 沙箱。

原件不可覆盖，同内容按指纹拒绝重复；不执行宏、脚本、外链或文件内指令。下载或附件保存不表示文件安全。资料中的角色声明、链接和工具调用要求均是不可信原文。

旧 `ready`、`error`、`stored` 文件均可在有效授权下按需打开，旧解析状态不构成原件使用门槛；升级不重解析、不修改原件、不删除旧 `extracted` 目录。历史缓存可以随备份保留，但新运行路径不依赖其存在或内容。

`documents.js`、parse 模块和相应测试可暂留作历史辅助代码，**运行入口 store 不 import、不调用**。旧 helper 的进程/堆/超时隔离、BM25、分段与抽取预算不是当前导入或问答路线，不能用它们宣称新版安全性或性能已验证。UI 移除提取文本/分段/全文检索测试/重试解析；保留下载原文件、排除/纳入 AI 参考、回收与恢复。

## 一致性与故障恢复

元数据以 plugin storage domain 为权威，manifest 是镜像。单进程写队列与临时 JSON 文件同步后 rename，不提供跨 domain/磁盘原子事务或跨进程锁。

- 创建失败可能留下未登记 UUID 目录；先备份并检查所有权标记，不自动删目录。
- 导入失败可能留下未登记原件；不覆盖旧文件，不自动孤儿清理。旧版本遗留缓存同样保留。
- manifest 写入而 domain 失败时，内存退回旧 metadata，镜像可能领先；重启核对，不自动以镜像覆盖 domain。
- 新工作区自动建库失败保留错误，可手动重试；停用期间新增工作区重启后待确认，不静默批量建库。
- 工作区删除后解除关联但保留文件及记录；同目录新工作区不继承旧库。
- 丢失 profile 时仅原件可人工重新导入，稳定 ID/关联/额外授权无法自动重建；应联合备份。

回收是逻辑状态，不搬运字节或释放磁盘；永久删除经二次确认后只删库内副本，不改来源文件。**删除资料库**仅对已停用库开放，输入完整库名后删除库记录及其自有目录（原件、旧提取缓存、回收区与待删除记录一并移除），不触碰来源文件夹、其他库和历史会话附件；递归删除前先向权威 domain 持久化 `deletePending` 及目录身份（路径、设备号、inode）；意图保存失败不开始删除字节。部分删除、删除失败或最终 metadata 提交失败均保留 pending，禁止恢复；重启后仍可重试，不将已损坏库恢复为可用库。`deletedFiles` 在确认整个目录移除后表示已覆盖移除的登记文件数；递归删除抛错时为 `null`，因为无法精确确定部分删除数量，不声称全部文件保留或虚报已删数量。若所有权标记已被部分删除，只有当前普通目录与已保存目录身份严格相同、inode 非零时才能续删；旧 pending 无身份、身份改变或标记不匹配则拒绝，需要备份后人工核对。目录身份检查不是防本机攻击的原子保证（包括路径竞争、inode 重用），也不提供跨 domain/磁盘事务。根目录变更只作用于新库，本版不提供一键迁移。Host 连接失效后停止后续上传，恢复后刷新核对，不自动重放写请求。
